Local client guide

Prepare. Review. Scan.

The public site is an introduction. Payments run from your local machine against an operator-reviewed ASP gateway. Keep the gateway token, payer key and signed requests private.

Set up the client

Use Node.js 22.13 or later. Follow the repository README to configure a reviewed gateway URL, recipient and local credential files.

Open client setup and source →

npm ci
npm run scan -- prepare --query query.example.json \
  --state .verun-client/scan.json

Preparation never pays. Review the returned recipient, amount, network and expiry before approving.

npm run scan -- pay --state .verun-client/scan.json \
  --approve-test-usdc

Recover the same scan

A timeout is not proof that payment failed. Keep the state file and check status. Retry resends the original signed request; it never signs a new payment.

npm run scan -- status --state .verun-client/scan.json
npm run scan -- retry --state .verun-client/scan.json

If the gateway reports reconciliation, an operator must establish the settlement outcome. Do not use a new request to recover it.

Use the results

The client prints the real gateway response, including the receipt. An empty scan is still a completed scan. Opportunity details, mandate checks and handoff preparation remain free through the gateway’s MCP tools.

Migration status

VERUN validator consensus, score gates and SBTs are retired. Legacy API calls return HTTP 410. The client does not execute investments. This candidate has not been activated or tested with a funded wallet.
